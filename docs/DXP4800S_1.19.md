## Implementation and limits

The existing model mapping is retained. `test-it8613-dxp4800s` now checks
hwmon pwm3/fan3 selection, the recovered single-fan direct mapping, rejection
of CPU targets, and that success/EIO/EBUSY/EACCES never trigger direct fallback.
Only ENODEV can enter the shared guarded direct path. Common controller
identity, ownership, locking, minimum PWM and write-readback checks remain
in the shared hardware layer; the app contains no new register operations.

Current implementation supports PWM/mode readback through hwmon or direct
register reads, manual PWM 40..255, and the `ugreenctl-fand` software curve.
The stock curve's lowest running point is 64; neither 40 nor 64 is a measured
stall-free minimum for this physical model. Stock automatic control is software,
not a hardware-auto mode. Physical PWM/RPM response, AC-loss behavior and
thermal margin still require exact-model testing. No physical writes were done.
LED support is maintained exclusively in LLLED_FPK's bundled LED CLI.
